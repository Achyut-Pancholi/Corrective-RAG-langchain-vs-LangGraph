Adaptive RAG (CRAG): LangChain vs. LangGraph
1. Problem Statement
Standard RAG retrieves documents once and generates an answer immediately, with no way to detect or recover from poor retrieval — a common failure with real knowledge bases. This POC implements Corrective RAG (CRAG): after retrieval, an LLM grades whether the retrieved documents are actually sufficient. If not, the system rewrites the query and retrieves again before generating a final answer.
The comparison is not “LangChain vs. LangGraph” as competing tools — it is plain RAG (a linear chain) vs. CRAG (a graph with a corrective loop). LangChain provides the shared components (loaders, retriever, vector store, prompts) in both flows. LangGraph is what makes the corrective loop possible: its StateGraph supports conditional edges that can route back to an earlier node, which a linear LCEL chain cannot express cleanly.
2. Objective and Scope
Build both flows over the same document set and the same underlying components, expose them via one UI with a toggle, and make the difference visible through an execution trace — not just a better 
final answer
.
Small fixed document set; vector store + retriever (Chroma/FAISS via LangChain)
Flow A: linear LangChain chain (retrieve → generate)
Flow B: LangGraph CRAG graph (retrieve → grade → conditional branch → rewrite-and-retry or generate), with a capped retry count to guarantee termination
Simple UI (Streamlit): flow toggle, question input, answer output, execution trace panel for Flow B
3. Approach
Both flows share the same retriever, vector store, and LLM configuration — the only variable is orchestration logic.
Flow A — LangChain (baseline)
Retrieve top-k docs → stuff into prompt → generate in one LLM call. No correction step; a bad retrieval produces a bad answer, by design — this is the limitation the POC exposes.
Flow B — LangGraph (CRAG)
Retrieve → grade node (LLM judges sufficiency) → conditional edge: sufficient → generate; insufficient → rewrite query and loop back to retrieval (capped at 2 attempts) → generate.
